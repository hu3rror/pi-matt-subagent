# Research child announces the in-process subagent lifecycle: the frozen non-emission reversed

> [ZH] 逆转 ADR 0014 冻结的「不为 in-process research 子会话发出生命周期事件」决策（父 issue #45，落地于 #46/#47/#48）：前提「无消费方」不再成立——gotgenes 权限系统（`@gotgenes/pi-permission-system`）的 gatekeeper 即 in-process 生命周期事件的消费方。research 子会话现在经父会话 `pi.events` 广播三个事件（`subagents:child:session-created` / `subagents:child:bound` / `subagents:child:disposed`，字符与权限系统订阅常量一致，由纯逻辑模块的常量与 payload 构造器钉死），并在提示前绑定扩展（`bindExtensions({ mode: "print", onError })`），使装载的权限系统得以激活。纯公告立场不变：本包从不订阅、从不读回，无订阅方时每次广播都是静默 no-op，`process.env` 永不改动；teardown 时 bus 失效引发的 stale-context 错误被工厂按 #32 既有模式吞掉，正常 run 不被误判为 rejection。blocking 通道（`PI_SUBAGENT_PARENT_SESSION`）与 toolCall audit 决策不受影响，README 不变（行为在无 gatekeeper 时是内部细节）。

ADR 0014 froze the in-process half of the subagent adapter convention for the research child: no lifecycle events, on the premise that no consumer existed. That premise is now false. The gotgenes permission system (`@gotgenes/pi-permission-system`) defines the in-process half of the convention — an in-process child announces itself by broadcasting lifecycle events on the parent session's `pi.events` bus — and the gatekeeper is now a consumer: per the convention, without the announcements a research child that loads the permission system is invisible to the parent — the child is never registered, its permission instance never activates, and an `ask` raised inside it has no forwarding path. This ADR reverses the frozen non-emission decision. ADR 0014's subagent-marker and toolCall-audit decisions stand unchanged.

## Decision

- **The research child adopts the in-process half of the gotgenes convention.** The extension (the parent session, wired via the factory's optional lifecycle hook to `pi.events.emit`) broadcasts the child's lifecycle in the convention's order — synchronous emit, a silent no-op on a bus with no subscriber:
  - `subagents:child:session-created` — emitted synchronously, on the same call stack with no `await` between session creation and the emit, immediately before `bindExtensions`, so a permission system registers the child before its own `session_start` activates inside it;
  - `subagents:child:bound` — emitted after `bindExtensions()` resolves, on the success path only; a binding throw propagates and the `finally` emits `disposed` alone (a child that never bound is not announced as bound);
  - `subagents:child:disposed` — emitted in the run's `finally`, on success and on error alike, so no stale child entry outlives the run.
- **An abort-before-start child emits nothing.** A child killed while the session is being created is disposed by the factory's post-creation abort check and rejects before any announcement, so the registry never sees a child that never ran.
- **The child binds its extensions before prompting.** `session.bindExtensions({ mode: "print", onError })` makes a loaded permission system activate (its child-side service publishes on `session_start`) and surfaces extension errors to stderr instead of dropping them silently. No UI context, command actions, or shutdown handler are bound — the child stays headless.
- **Channel names and payload shapes are pinned, not implied.** The three channel constants (`SUBAGENT_CHILD_SESSION_CREATED` / `SUBAGENT_CHILD_BOUND` / `SUBAGENT_CHILD_DISPOSED`) live in the pure logic module, declared character-identical to the permission system's subscriber constants — the identity is by construction (the two sides declare independently and no cross-package pin exists), so tests pin the plugin side only. The payload builder (`buildSubagentChildAnnouncement`) is the single source of truth: `session-created`/`bound` carry `{ sessionId, parentSessionId? }`, `disposed` carries `{ sessionId }`; `parentSessionId` is omitted as a key (never `undefined`) when the run has no parent session. Both are pinned by the pure-logic tests (issue #46) and observed against a live session by the dev-only real-pi gates (`scripts/push-e2e.ts`, gates 7–9b, issue #48): emission ordering, abort-before-start silence, and the bound child's output/loadout lines unchanged.
- **Pure announcement preserved.** Nothing in this package subscribes to the channels and nothing reads an announcement back; without a subscriber every emission is a silent no-op (no permission system installed, or installed but not loaded into the child). The plugin's own `process.env` is never mutated. At teardown, an emission on the bus invalidated at `session_shutdown` throws pi's stale-context error; the factory swallows exactly that error (the runner's established #32 pattern) so a normal run's shutdown is not turned into a confusing rejection — the pure-announcement stance holds at teardown.
- **The blocking channel and the audit seam are untouched.** Blocking children still announce via `PI_SUBAGENT_PARENT_SESSION` per spawn (ADR 0014's marker decision), and the `toolcalls.jsonl` audit decision is unaffected.

## Supersedes

- ADR 0014's **Deliberate non-emission: in-process lifecycle events for the research child** section, and its considered-options entry "Emit gotgenes in-process lifecycle events for the research child — rejected: no consumer exists." The premise is dead; ADR 0014's other two decisions (the subagent marker and the toolCall audit shape) stand.

## Consequences

- With the permission system installed **and** loaded into the research child (`researchChildExtensions`), the announcements enable the gatekeeper's consumption: per the permission system's subscription contract, the parent registers the child at creation and unregisters at disposal, and a child that loaded no permission node is reported via the `bound` audit. This package guarantees only the announcements themselves (timing, channels, payloads); the consumer-side behavior belongs to the permission system and is not verified here.
- Without the permission system (or without it in the knob), research behavior is unchanged: every emission is a silent no-op.
- Binding is a real behavior change, not a cosmetic one: a loaded package's `session_start` handlers now fire, unhandled MCP-server reporting runs, and `resources_discover` may re-assemble the system prompt. The dev gates assert the quiet default stays structurally unaffected (zero loaded extensions → no `resources_discover` handlers); the bound-child output and loadout lines are observed unchanged with a knob package loaded (gate 9).
- The convention stays one-way: the plugin emits and never reads the events back, so a future contributor should not grow a reader inside this package (the same stance as the env marker in ADR 0014).
- No README change: the behavior is internal unless the gatekeeper is present, and both READMEs do not mention the marker or the lifecycle events.
