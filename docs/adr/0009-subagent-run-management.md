# Manual run management: kill / prune / tail through the /subagents command

ADR 0004's overview is display-only: the footer counter and `/subagents` snapshot show every run, but nothing is operable — a runaway background researcher can only be killed by the hard-cap watcher (grace deadline / log 110% backstop, minutes away at best), finished runs accumulate for the whole session, and a run shows only its truncated last line plus file paths. We add the first management surface as an extension of the existing command: `/subagents` without args opens an interactive menu (snapshot / kill / prune / tail; kill and tail filter to eligible runs in a second select), with-args runs the operation directly (`kill <id>` / `tail <id>` / `prune`). Scope is deliberately narrow: **kill** (manual terminate of a running background research), **prune** (drop terminal runs' registry entries, files kept in tmp), **tail** (last log bytes via the existing `readLogTail` cap). Explicitly out of v1: per-task cancellation inside a parallel blocking call (input queues during blocking runs — commands are unreachable, Esc aborts the whole call and stays the only mid-blocking control), retry (background runs are coupled to the main session's context and artifacts; no overwrite/consistency story yet), an agent-facing management tool (the LLM cannot see a command's notify output, so it would need a parallel query surface plus a destructive-op boundary), and a TUI pager/editor (would blow the display budget; tail via byte-capped `readLogTail` stays lean).

Semantics and safety: a manual kill is a user-initiated abort — the run resolves to `aborted`, never `failed` and never `terminated` (which stays reserved for hard-cap kills, marker-based). The kill path pre-registers a kill intent (`abortIntent`, an extension-side set) *before* sending the signal, so the watcher's `onExit` — which fires with a non-zero exit code for a signal kill — resolves to aborted instead of failed; the intent set is cleared on `session_shutdown` and opportunistically pruned during prune (drop ids whose registered run is already terminal). Kill is guarded: only runs with `status === "running" && pid != null` are eligible — a finished run must never be re-killed, since PID reuse could deliver the signal to an unrelated process — and ESRCH from the kill call is swallowed as success (the child was already gone). No SIGTERM grace period: the kill is hard, platform-split — POSIX `process.kill(-pid, "SIGKILL")` (the research child is spawned `detached`, so the negative pid reaps its bash/python grandchildren) and Windows `taskkill /pid <pid> /T /F` (node's `child.kill` has no tree semantics on Windows — a plain kill would orphan grandchildren). The checkpoint mechanism makes the hard cut acceptable: a killed run loses at most one search round of findings. Prune only touches terminal runs, short-circuits with a notify when there is nothing to clean (no empty confirm), and confirms before dropping entries. The registry gains one optional field — `pid` on background runs (serializable, displayable, single source of truth); the kill intent stays extension-side so ADR 0004's public data model stays clean.

## Considered options

- **Registry-side child map / abort channels in RunEntry** — rejected: the registry is ADR 0004's pure in-process data model; process handles belong to the runner. `pid` is the minimum serializable fact the command needs; the watcher already owns the child.
- **SIGTERM then SIGKILL grace** — rejected: the researcher's signal semantics are unverified and checkpoints bound the loss to one search round; a grace phase adds state for no gain (ADR 0008 reached the same conclusion for hard-cap kills).
- **Interactive TUI panel or pager** — rejected (re-affirming ADR 0004): persistent widgets need invalidate plumbing and occupy screen space; a pager needs its own buffer story. Menu-via-select keeps everything inside the existing command surface.
- **Agent-facing management tool** — deferred: the LLM cannot see a command's notify output, so the tool would need a parallel query surface; destructive operations by the agent need a boundary story. Listed as an enhancement, as in ADR 0004.

## Consequences

- `aborted` now has two sources (blocking Esc and manual kill of a background run); `terminated`'s marker-based meaning is untouched.
- `pid` becomes the registry's only runtime-adjacent field; kill-by-pid is the single kill path shared by menu, args, and any future surface.
- The watcher's `onExit` must tolerate already-terminal runs (no-op) for the kill-vs-exit race; `abortIntent` is the authoritative "who killed it" memory, bounded by `session_shutdown` + prune-time consistency cleanup.
- A manually killed run leaves partial findings — checkpoint-bounded; the `research-terminated` marker is absent (that is the hard-cap path's signature), so the reader judges completeness by content, mirroring ADR 0003's stance.
- Footer counter and snapshot rendering are unchanged; menu and args are the same `/subagents` command, so no keybinding/panel plumbing enters the TUI.
