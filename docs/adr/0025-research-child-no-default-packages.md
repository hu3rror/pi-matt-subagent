# Research child loadout: no default packages, activation follows load

> [ZH] 撤销 #37 的默认装载决策：research 子会话不再默认装载任何扩展包——`researchChildExtensions` 改为非可选、空默认（安静默认，只有内置工具、无网络），「装载」与「激活」解耦为单向：**装载即激活**。内置 researcher 角色的工具表收窄到内置名；`set` 逗号列表装载包、`config reset` 回到空默认；`inherit` 对该旋钮无意义（没有可继承的东西）。工具探测额外回报包工具名（`packageToolNames`），runner 在无显式 `tools` 时把它们并入 allowlist（显式列表仍唯一权威、不并入），结果照旧过递归防护（本扩展工具永不进子会话）。空装载时 loadout 自报一行 `[loadout] info · no query packages configured`；装载了包却什么都没注册时照旧 `[loadout] warn` 并点名包。README（双语）与 release notes 面向既有用户写明升级影响（升级后 research 子会话失去 web/库文档能力，需要显式配置），信任判据（只读、无外部写副作用、外部成本低且明确、服务一手来源检索）保留在文档里作示例判据，不再有代码默认清单。dev-only 真实 pi 脚本（push-e2e）门改为：安静默认装载只有内置工具、装载的包无需角色声明即激活其工具、两种情形都无 drift 行。

Issue #37 shipped a curated default loadout for the research child: `npm:@ssk_dev/pi-web-access-lean` + `npm:@upstash/context7-pi`, active for every user who never touched the knob. Two failure modes followed. First, a package that is not installed on a machine still sits in the default list, so every research run carries a warning the user can only silence by hand-editing a JSON file. Second, the shipped researcher role declared the packages' tool names (`web_access`, `query-docs`, `resolve-library-id`), so emptying the list produced permanent drift reports for capabilities the user deliberately removed — and, in the other direction, a loaded package's tools were only visible when a role happened to name them, coupling loading and activation. Issue #44 reverses the default-on decision: the extension ships no default loadout, packages are a choice, and a chosen package's tools become usable without editing any role file.

## Decision

- **The knob becomes non-optional with an empty default.** `researchChildExtensions` defaults to `[]`; the effective value is the knob itself — no curated fallback constant, no "absent means defaults" reading. The `inherit` token (and the menu/CLI surface for it) is removed for this knob: there is nothing to inherit from; `config reset researchChildExtensions` returns to the quiet default. Because the key is non-optional, serialization always writes it (an explicit `[]`), and a written-but-default `[]` labels `[default]` — the config view compares the extensions value by content, not by array identity.
- **Activation follows load.** The child's allowlist is the resolved role declarations (built-in / runtime-resolved names) **unioned with** the tool names the loaded knob packages provide. When the caller passes an explicit `tools` list, that list is authoritative and no package tools are added. The union passes through the existing recursion guard (this extension's own tool names never reach a child, even when the knob names this package).
- **The bundled researcher role declares built-in names only** (`read`, `grep`, `find`, `ls`, `bash`, `write`); `DEFAULT_RESEARCH_TOOLS` (the fallback for roles without tools) is reduced to the same built-in set, so an unconfigured knob produces no drift on either path. A custom role that names a package tool still works when the package is loaded and is drift-reported when it is not.
- **The probe grows a package half.** `researchChildToolNames` (and `probeChildToolNames`) now also report `packageToolNames` — the names the knob packages registered — which feed the runner's activation union. The blocking path keeps its full-registry probe; its package half is empty.
- **The child-session options take the extension list as always-present.** The `extensions` parameter is a required `string[]` on the child factory; the legacy "no extensions at all" (`noExtensions`) branch is dead and removed. An empty list is the quiet default (built-in tools only); the runner normalizes an absent value to `[]`.
- **The loadout report keeps its shape and only speaks when the knob is non-empty; the empty case gets one informational line** — `[loadout] info · no query packages configured — child carries built-in tools only` — so the run log says explicitly why the child has no web/library-docs tools.
- **The trust criterion survives in the documentation**, not in code: the README keeps the curated criterion (read-only, no external write side effects, low and explicit external cost, primary-source retrieval) and names the two vetted packages as examples of the one-step procedure (put the package in the knob; its tools activate automatically).
- **Existing users' upgrade is documented, not silent**: release notes, both READMEs, and the empty-knob log line explain that research children lose web and library-docs access until the knob is configured. No automatic config write — the surface only writes on explicit set/reset.

## Consequences

- An unconfigured install is quiet: no warning, no drift, a research child with built-in tools only (no network).
- Configuring `researchChildExtensions` to a package is one step: the package's tools join the child's allowlist without touching any role file. A caller can still dispatch a deliberately narrower researcher via an explicit `tools` list, which stays authoritative.
- A custom researcher role that names a package tool keeps working when that package is loaded, and its absence is loudly reported (the drift receipt + `[research-drift]` log line) — the same error shapes as before, now only when the user configured something.
- The recursion guard is preserved: the extension's own tools never enter a research child, even if the knob names this package.
- ADR 0013's "the child loads exactly the approved query packages (default …)" note and ADR 0018's knob-set note are superseded by this ADR; the loadout self-report line remains the post-hoc verifier.
